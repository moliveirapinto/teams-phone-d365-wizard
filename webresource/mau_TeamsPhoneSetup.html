Step 2 — Run this once in PowerShell

Run as a Teams Administrator + Global (or Application) Administrator. Safe to re-run: it only changes what is missing, then proves the result.

PowerShell 5.1 or 7+
Downloaded file blocked? Run Unblock-File .\Onboard-TeamsPhone.ps1 or powershell -ExecutionPolicy Bypass -File .\Onboard-TeamsPhone.ps1. The script ends with a PASS/FAIL table. Come back here only when it says ALL CHECKS PASSED.

Troubleshooting
SymptomWhat to do
Sync says "No new phone numbers were found" or TotalTeamsNumbers: nullD365 cannot match the Teams resource account. Re-run the script (it verifies and repairs ApplicationId and AcsResourceId), wait ~5 minutes, sync again.
Resource account type shows Other in Teams adminExpected. Never change it to Call queue or Auto attendant in the Teams UI: that swaps its ApplicationId to the Call Queue app and breaks the binding. Re-run the script to repair.
"Unable to find repository 'PSGallery'"PSGallery is blocked or unregistered. Run Register-PSRepository -Default, or install MicrosoftTeams and Microsoft.Graph.* from your internal feed, then re-run.
"You don't have access to the Teams admin center" (INVALID_PRIVILEGE)Open the dashboard first and navigate with the menu. If it persists, the account lacks the Teams Administrator role.
Automatic number assignment failed (Calling Plan)Teams admin center → Voice → Phone numbers → select the number → Edit → Assigned to: Resource account → pick the account → Apply. Then run Sync again.
License warningAdd the free Microsoft Teams Phone Resource Account license in M365 admin center → Billing → Purchase services, then re-run the script.
Banner "Some components require you to sign in" in D365Click Sign in once and allow the popup. It is not what blocks the sync.
